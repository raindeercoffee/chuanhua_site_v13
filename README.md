## 🎨 v10 新增:專屬底色調色工具(像小畫家一樣拖拉每頁底色)

### 怎麼打開調色盤
兩種方式(擇一):
1. **網址加 `?edit`**:例如用瀏覽器開 `index.html?edit`
2. **按快捷鍵 `Ctrl + Shift + E`**:在網站任何地方按,調色盤就會從右上角跳出來

平常訪客看到的網站不會有這個面板,只有你自己加參數/按快捷鍵才會出現。

### 怎麼用
- 面板列出 **7 頁**,每頁有兩個色塊:**頂(頂部色)** 和 **底(底部色)**——因為每頁底色是上到下的漸層
- **點色塊 → 跳出取色器 → 拖一拖,那一頁的背景即時就變**
- **文字深淺會自動處理**:底色調深,標題文字自動變白;底色調淺,文字自動變回深色(白色卡片裡的字一律維持深色)
- **改了就自動存**,重開網站顏色還在(存在這台電腦的這個瀏覽器)

### 可調的 7 頁(其餘刻意不含)
關於我們 / 我們做的事 / 我們開過的花 / 兩種開花的方式 / 開花的流程 / 退款規則 / 品牌有了想法
> 花園(進入頁)、河岸(進入後第一頁)、開花教室、聯絡+頁尾 **不列入**,照需求排除。

### 兩顆按鈕
- **匯出色碼**:按了會出現一段 CSS 色碼(也自動複製到剪貼簿)。等你調到滿意、想「永久固定」到檔案,把這段丟給我,我幫你寫回 CSS 就固化了
- **重設全部**:清掉所有調過的顏色,回到預設

### 重要提醒(localStorage 的特性)
調的顏色是存在「你這台電腦的這個瀏覽器」裡:
- ✅ 同一台電腦、同一個瀏覽器,重開網站顏色還在
- ⚠️ **換電腦、換瀏覽器、或正式上線給別人看,顏色不會自動跟著走** → 這時就要用「匯出色碼」把顏色固化進檔案(丟給我貼回,或我教你貼)

## V9 修復:花朵「出現完就消失」的 bug(只改花,其他全未動)

**原因**:v8 把搖曳動畫(`g-sway`,轉動)跟浮現動畫(`g-rise`,淡入+放大)套在同一個 `<img>` 元素上。搖曳動畫啟動的瞬間,CSS 會用「後面宣告的規則整組蓋掉前面的」,導致浮現動畫連同它保持的 `opacity:1` 一起被蓋掉,畫面掉回最初的 `opacity:0` = 花消失。

**修法**:把 `<img>` 包一層 `<span class="g-imgwrap">`,浮現動畫留在 `.g-img`,搖曳動畫改套在外層 `.g-imgwrap`。兩個動畫分屬不同元素,不會再互相蓋掉,花會正常浮現後留在畫面上搖曳。

**驗證**:已用 diff 確認這次只動了花朵動畫相關的 4 處(CSS 規則 + HTML 樣板),README/package.json/其他區塊全部零差異。

## V8 更新:開場五朵花改成「可替換圖檔」(只動花,其他全未動)

原本五朵花是程式即時畫的 SVG,無法換圖。本版改成引用 `assets/` 裡的五個圖檔,**你手繪好之後,用同檔名覆蓋掉舊檔就會自動替換,不用改任何一行 code。**

### 五朵花檔名對照(從左到右)
| 位置(左→右) | 檔名 | 點下去會到 |
|---|---|---|
| 第 1 朵(最左) | `assets/flower_1_farLeft.png` | 關於我們 |
| 第 2 朵 | `assets/flower_2_left.png` | 我們開過的花 |
| 第 3 朵(中間最高) | `assets/flower_3_center.png` | 開花教室 |
| 第 4 朵 | `assets/flower_4_right.png` | 開花的流程 |
| 第 5 朵(最右) | `assets/flower_5_farRight.png` | 找川花說話 |

### 替換方式
1. 手繪好一朵花,存成 **PNG、去背(透明背景)**,尺寸建議直向、含莖(底部就是莖的末端,網站會讓五朵花「底部對齊」)
2. 檔名取成上表對應的名字,覆蓋掉 `assets/` 裡的同名舊檔即可
3. 目前這五張是**暫時占位圖**(用程式畫的,跟舊版長得一樣),換成你的手繪後就會顯示你的

### 因為改成圖片,動畫有一點點變化(其餘全保留)
- 舊版:莖會「描線一路長上來」再開花(這是 SVG 才做得到的)
- 新版:整朵花「由小放大、輕輕升起淡入」,一朵接一朵出現;之後的**搖曳、點下去摘花+花瓣飄散+進入對應頁**全部保留
- 因為你要用「整朵手繪圖」替換,本來就無法做描線生長,所以改成放大浮現最合適

## 為什麼沒有 node_modules / dist?
本版是「零依賴純靜態網站」:index.html + assets 就是全部。雙擊 index.html 就能看,不需要 npm install、沒有編譯步驟(所以沒有 dist、node_modules)。這是刻意設計,最輕、最不會壞。package.json 只提供本機預覽指令;.git 為版本記錄——結構因此和 chuanhua_site_v2(Vite 專案)不同,但檔案是完整的。
